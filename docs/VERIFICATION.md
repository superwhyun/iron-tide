- 최종 로컬 프로덕션 서버에서 사진 재질은 `image/jpeg`, 녹음·무전은 `audio/wav`, NPC GLB 2종은 `model/gltf-binary`로 200 응답하는 것을 확인했습니다. 실제 프로덕션 WebSocket으로 Golden NPC와 전투를 생성하고 기뢰 3발·로켓 6회·정확도 0단계를 수신했습니다.
- 로컬 프로덕션 서버에서 화면 로드·방 생성 성공, 브라우저 예외 없음, 개발용 진단 객체 제거 확인.

## 재현 조건과 직접 검증하지 못한 부분

- 브라우저 전투 테스트는 테스트 서버의 비밀키로 보호된 fixture로 함선 위치·방향을 정렬합니다. 어뢰 격침 장면은 표적 체력을 낮추고, 복구·수리 장면은 피해 상태를 준비합니다. 조작·발사·탄도·충돌·피해·경험치·강화는 실제 UI와 서버 경로를 사용합니다.
- 경기 종료 확인은 서버 시뮬레이션을 기본 30Hz로 남은 경기 시간만큼 빠르게 진행합니다. 사람이 8분 동안 연속 플레이한 결과와 구분합니다.
- 이 실행 환경에서는 최소 HTML 예제에서도 Chromium의 마우스 잠금 요청이 거절되었습니다. 게임의 대체 마우스 입력으로 회전·조준·사격을 검증했습니다. 일반 사용자 PC에서의 네이티브 마우스 잠금 성공은 직접 확인하지 못했습니다.
- 세부 모델·사진 재질 적용 후 소프트웨어 렌더링 환경에서 네 브라우저를 한 PC에 동시에 실행했을 때 3–4fps, 단일 대기실 녹화에서는 약 15fps를 관측했습니다. **일반 PC의 GPU에서 1080p·60fps 달성은 미검증입니다.** 네 플레이어가 서로 다른 PC에서 교전하는 성능을 이 수치로 대신 주장하지 않습니다.
- 다른 실제 PC와 Wi-Fi/인터넷을 통한 연결은 확인하지 않았습니다. LAN 접속을 지원하는 로컬 서버 구조이며 외부 배포·공개 매칭은 포함하지 않습니다.
- 플레이어 함선과 지형 메시를 직접 만들고, NPC에는 사용자 제공 GLB 2종을 사용합니다. 사진 기반 재질과 CC0 녹음 효과음, 별도 생성한 무전 음성을 로컬 자산으로 사용합니다. [출처·가공 기록](../assets/ATTRIBUTION.md)을 참고하세요. 실함의 정밀 복원 모델이나 원작 그래픽을 복제한 결과는 아닙니다.

## 사실성·조작 수정

- 곡면 선체, 갑판, 함교 유리, 난간, 구명정, 마스트·삭구, 포탑과 개별 포신을 갖춘 세 함종으로 교체했습니다. 고정 부품은 재질별로 병합합니다.
- 원뿔·덩어리 형태의 섬을 연속적인 높이 지형으로 교체했습니다. 불규칙한 해안선과 능선, 경사·고도에 따른 암벽·모래·식생 재질을 사용합니다. 서버의 해안 충돌·섬 시야 차단·포탄 지형 충돌과 미니맵이 같은 지형 계산을 사용합니다.
- 포탄 탄체·예광 궤적, 포구 화염·포연·반동, 착수 물기둥·물방울·파문으로 효과를 교체했습니다.
- 실제 MK45 함포 녹음, 대포·원거리 폭발 녹음을 조합합니다. 저음 레이어, 거리 감쇠·필터·전파 지연·좌우 패닝과 잔향을 적용합니다. 대기실에서 전함 선택 후 `주포 시연 · 음향 듣기`로 혼자 확인할 수 있습니다.
- 기존 주포 시연의 최종 Web Audio 출력을 MediaStream으로 녹음한 `artifacts/cannon-mix-preview.wav`는 10.86초입니다. 기본 음량 72%에서 피크 -2.5 dBFS, 전체 RMS -19.1 dBFS, 32–110Hz 대역 RMS -25.5 dBFS를 측정했습니다. 클리핑 없는 이 단일 전함 시연을 확인한 결과이며, 여러 함선의 동시 포격 전체나 실제 스피커·우퍼의 물리적 재생 품질을 검증한 결과는 아닙니다.
- A/D 조타와 마우스 회전의 좌우 부호를 수정했습니다. 브라우저 항해 시나리오에서 오른쪽·왼쪽 모두 방향을 검증하고 한글 입력 상태의 물리 키 처리도 확인합니다.
- Three.js 셰이더 컴파일 오류를 놓치지 않도록 브라우저 검증에 콘솔 오류 수집을 추가했습니다. 재질 교체 도중 발견한 GLSL 예약어 사용 문제를 수정하고 화면을 다시 확인했습니다.
- 쌍안경 시점에서 내 배의 마스트가 화면을 가리지 않도록 자체 함선을 숨깁니다. 연막은 불투명한 다면체 대신 겹치는 반투명 연기 스프라이트를 사용합니다.
- `artifacts/realism-island.png`는 `scripts/capture-terrain.mjs`가 게임과 같은 SeaScene을 HUD 없이 렌더링한 근접 검토 화면입니다. `artifacts/browser-island.png`는 실제 두 브라우저 전투 시나리오에서 촬영한 화면입니다. `node scripts/capture-presentation.mjs`는 세 함종 화면과 게임의 실제 최종 오디오 출력을 재생성합니다. 이 두 캡처 스크립트는 개발 서버 5173이 켜져 있어야 합니다.

## NPC·항해 음향·무전 추가 검증

- 함대장이 NPC를 추가·삭제하고 사람과 합쳐 4척 제한을 지키며, 혼자 NPC와 출항하는 흐름을 실제 UI에서 검사합니다. NPC는 같은 서버 규칙으로 항해·포격·어뢰·기뢰·요격 로켓·강화를 사용합니다. 사람만 함대장 권한을 인계받습니다.
- `public/models/npc-battleship.glb`와 `npc-wisconsin-golden.glb`는 사용자가 지정한 원본과 SHA-256이 일치합니다. GLB의 재질을 보존하고 별도 회전·고각·반동 포탑을 추가했습니다. Golden은 406mm 3연장 3기입니다. 브라우저에서 해당 변형 로드 완료, 포탑 3기, 실제 NPC 발사·이동을 확인합니다.
- `artifacts/npc-wisconsin-golden-bow.png`와 `npc-wisconsin-golden-side.png`는 같은 게임 모델을 근접 확인한 화면이며, `browser-npc-battle.png`는 실제 경기 화면입니다.
- 실제 속력·기관 부하에 따른 엔진 녹음 1개와 물살 녹음 1개를 연속 재생합니다. 어뢰는 압력 방출과 세 번의 입수음입니다. 12개 한국어 명령은 Microsoft InJoon 신경망 음성을 WAV로 저장한 것으로, 대역 필터·약한 잡음·송수신음을 적용했습니다. 배우의 연기나 실제 전장 통신 녹음은 아닙니다.
- `tests/browser/npc-audio.spec.ts`는 실제 최종 AudioNode 출력에 MediaRecorder와 분석기를 연결합니다. 음원 재생 카운터 외에 정지/전속 음량 차이, 어뢰 발사 후 출력 증가, 전체 음향 끄기·퇴실 후 무음, 무전 자막·중복 방지·방향 명령을 검사합니다. 원본 결과는 `navigation-radio-mix.webm`, 측정은 `navigation-radio-levels.json`에 저장합니다. 물리적 스피커·우퍼 청취 품질은 별도입니다. 이번 최종 실행의 정지 RMS는 0.00794, 전속은 0.04010으로 약 14.1dB 증가했습니다. 78.06초 녹음 파일의 디코딩 피크는 −1.0dBFS입니다. `torpedo-radio-preview.wav`는 이 녹음에서 어뢰 발사 직전부터 24초를 자른 청취용 샘플입니다.

## 착탄 분산·기뢰·요격 로켓 추가 검증

- 클라이언트의 수면 원과 서버 사격이 같은 `shared/ballistics.ts`를 사용합니다. 실제 발사한 72발의 착수 위치가 표시 반경 안에 들어오는지 검사하고, 6,000개 무작위 표본의 면적 분포도 검사합니다. 중간에 함선·지형과 충돌한 탄은 해당 위치에 먼저 명중합니다.
- 함종, HE/AP/SAP, 거리, 일제 확장, 사격 관제 강화에 따라 반경이 달라집니다. 사거리 55%를 넘으면 분산 증가가 더 가팔라집니다. 관제 3단계는 기본 반경의 64%입니다. 마우스 상하 조준에 따른 거리와 포신 고각도 연결했습니다.
- SAP의 경장갑 피해와 중장갑 비관통, 기뢰의 2초 신관·근접 탐지·1회 폭발·설치자 면역·탄수·90초 수명, 로켓의 실비행·재사용 제한·적 어뢰 3발 제거·함선 무피해, 보조 무기 전환 후 기존 주포 재장전 유지가 규칙 테스트에 포함됩니다.
- 장갑 비교는 120m에서 부포를 끈 동일한 일제사격 두 번을 사용해 각도를 준 측면과 노출한 측면의 피해를 비교합니다. 도탄은 실제 수신된 서버 이벤트로 확인합니다. 전함 일제사격으로 순양함이 침몰하면 재출격을 마친 뒤 별도 섬·음향 탐지 배치를 준비합니다.
- 새 브라우저 시나리오는 실제 키보드와 마우스로 조준, 정확도 강화, SAP 발사, 기뢰 설치, 로켓 발사를 수행합니다. 시험용 API는 상대 함선을 기뢰 위에 배치하고 두 척의 초기 교전 위치·체력을 준비합니다. 어뢰는 상대 브라우저에서 직접 발사하며, 방어 수역을 미리 조준한 뒤 접근 시 로켓을 발사합니다.
- 착수는 구경별로 더 큰 물기둥·물방울·안개·확장 파문을 사용하며, 실제 물소리 녹음과 저음·거리 감쇠를 혼합합니다. RBU는 이 게임의 수동 수역 방어 무기이며 실물 성능을 재현한 군사 시뮬레이션은 아닙니다.
- 화면 근거: `browser-dispersion-circle.png`, `browser-mine-laid.png`, `browser-rbu-interception.png`.

## 좌초·정밀 시점·표면 명중·침몰 연출 수정

- 좌초 때 매 틱 속력 전체를 감쇠하던 처리를 해안 법선 방향의 진입 성분만 막고 접선·이탈 성분은 유지하는 처리로 바꿨습니다. 겹쳐 들어간 선체는 해안 바깥으로 복구합니다. 기관이 작동 중인 해안 접촉 상태에서는 낮은 속력에도 조타력이 남습니다. W/S는 한 번 누르면 한 단계, 길게 누르면 연속 변경하고 키를 놓으면 항속을 유지합니다. 화면에 해안 접촉과 서버가 받아들인 기관 명령을 표시합니다.
- `shared/hullShape.ts`의 곡면 선체·갑판 기하는 플레이어 모델과 서버가 공유합니다. 상부 구조물과 추가 포탑은 별도 단순 충돌체입니다. NPC 2종은 원본 GLB의 삼각형과 노드 변환을 읽고 클라이언트와 같은 중심·수면 높이·90도 회전·배율을 적용합니다. 서버는 BVH로 3D 구간과 표면의 최초 접촉을 찾습니다. 파도에 의한 작은 시각적 흔들림과 추가 포신·장식까지 모두 물리적으로 복제한 것은 아닙니다.
- 기존의 '2D 사각형 진입점 + 높이 -2~15m' 판정을 제거했습니다. 실제 접촉점·표면 법선·갑판/측면/선수·함미/상부 구조물/포탑을 사용하고, 상부 구조물에는 중장갑 측면 수치를 적용하지 않습니다. AP의 얇은 판재 구경 우세도 반영합니다. 도탄·비관통 규칙은 유지하며 명중 확인과 체력 피해를 구분해 표시합니다. 재출격 보호에 막힌 접촉도 이유와 함께 표시합니다.
- 사망 직후 탐지 목록에서 빠진 표적의 ID가 공격자 이벤트에서도 사라져 침몰 연출을 연결하지 못하던 문제를 수정했습니다. 공격한 플레이어와 방금까지 표적을 보던 플레이어의 침몰 이벤트에는 표적 ID를 유지합니다. 미탐지 함선의 현재 좌표·체력 비공개 규칙은 유지합니다.
- Shift와 휠은 카메라가 이동한 뒤에도 같은 수면 좌표를 보도록 시야 각도를 다시 계산합니다. 쌍안경의 최소 하향 각도를 완화해 1,400m 이상의 기존 조준점도 유지합니다. 시점 전환은 이미 발사한 포탄에 영향을 주지 않습니다.
- 피해 숫자는 72px, 3초 유지이며 새 피해는 기존 표시 위에 쌓입니다. 같은 순간의 같은 판정만 합산합니다. 피해 크기별 색상·명중 마커·대상 옆 숫자·일제사격 합계·판정별 횟수·장갑/입사각을 함께 표시합니다. 별도 컴포넌트 검사로 크기·색상·중첩·유지 시간을 확인합니다.
- 관통 화염·파편·검은 연기를 강화했습니다. 침몰은 원본 모델을 GPU 클리핑으로 두 조각으로 나누고 파손 단면·내부 골조를 덧붙여 별도로 회전·하강시킵니다. 갑판 화염·연기·증기를 더하며 13초 후 정리합니다. 실제 메시를 물리적으로 파괴하는 유체 시뮬레이션은 아니며 재출격 규칙과 독립적인 시각 연출입니다.
- 새 규칙 검사는 세 함종의 좌초 조타·후진 탈출, 해안 안쪽 겹침 복구, GLB 표면/빈 공간·회전·위치, 하강탄 3D 접촉, 구경 우세·얇은 상부 장갑, 재출격 보호 명중 알림, 침몰 표적 ID 유지, 80/500/1,400/2,100m 시점 왕복을 포함합니다.
- 새 브라우저 검사는 실제 S 길게 누르기 탈출, Shift 왕복 좌표 비교, 비관통·피해 표시, 실제 AP 격침과 두 조각 연출을 확인합니다. 별도 모델 컴포넌트에서는 브라우저 GLTFLoader/Raycaster로 읽은 두 원본 GLB의 18개 광선과 서버 충돌 결과를 비교했습니다. 침몰 장면은 같은 Wrecks 코드에 시점을 고정해 1/4/8초를 렌더링한 컴포넌트 검토 화면입니다.
- 화면 근거: `browser-coastal-escape.png`, `browser-confirmed-nonpenetration.png`, `browser-hit-split-sinking.png`, `browser-damage-stacking.png`, `wisconsin-sinking-explosion.png`, `wisconsin-sinking-breakup.png`, `wisconsin-sinking-submerged.png`.

## 실행 상태와 Git

개발 화면은 `http://localhost:5173`, 서버 상태는 `http://localhost:3000/health`입니다. 두 프로세스는 `npm run dev`로 함께 실행합니다.

Git 저장소는 `main` 브랜치이며 원격 `origin`은 `https://github.com/superwhyun/iron-tide.git`입니다. 소스·문서·실행 자산·출처 자료·검증 결과물을 관리합니다. `node_modules/`, `dist/`, 테스트 임시 보고서는 제외하며, 실행 시 의존성 설치와 빌드로 재생성합니다. GitHub 소스 보관과 외부 게임 서버 배포는 별개이며 외부 서버에는 배포하지 않았습니다.
